  history, not a claim about natural user-history quality.

  is allowed. The task reconstructs eighteen policy fields, including two

- Two fresh CLI tasks per condition/version, ordered OFF/ON then ON/OFF.
  OFF has no memory service. ON exposes all twenty real MCP tools, not a
  search-only catalog; its isolated adapter admits the required reads only.
- Current model, reasoning setting, normal host/skill discovery and read-only

- Each timed task includes CLI startup, file/skill reading, tool round trips,
  reasoning and the final JSON answer. Independent checking then compares the
  eighteen actual output fields with the source decisions. It is not a search-
  latency microbenchmark, but neither is it an ingestion-to-retirement lifecycle.

## Remaining conclusion

This establishes a useful warm-memory long-history consumer case. It does not
erase the earlier short-history negative result. Repeated workloads, naturally
collected history, controlled cache conditions and measured construction/
maintenance cost are still needed for a general or full-lifecycle efficiency
claim. Further fixed-context reduction needs a validated host discovery/loading
path, not weaker evidence or another product-facing memory surface.
