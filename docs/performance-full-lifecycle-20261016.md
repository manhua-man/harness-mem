## 失败、恢复与声明边界

1. HM 初始采集器上下文错误：未启动产品模型，保留零请求收据，准确初始化耗时未记录。
2. HM 第 95 场：模型流只有部分 JSON/大量尾部空白，240 秒采集器阈值先于原生产品超时；另有超时清理误拒 `nul` 的驱动错误。两次请求无最终 usage。只修任务驱动，采集器阈值改为大于未改变的产品阈值，从同一 job 恢复，不重建前 94 场。
3. CM 第 67 场：一次原生 180 秒 provider deadline；驱动误把保留工作的 transient 判成失败，关闭 worker。恢复时又因合法零观察成功仍保留旧错误元信息而误停。前 66 场未重建，原文/会话/Read ID 相同；native RAM buffer 跨重启丢失，按原生原文重放路径恢复，不能称 exactly-once 模型处理。失败及额外真实调用全部在账内。
4. CM 更正入口：一次 CRLF 字节校验失败、一次把已恢复但保留历史错误元信息的 ledger 误判为新故障，均零模型请求。修任务驱动，不清除原生日志、不改官方产品代码。
5. 最后消费者采集器：TLS handshake `ECONNRESET`，零请求，旧目录保留，新目录执行同题。没有模型答案被筛掉。
6. 独立审查指出健康日志原位写入可能造成半截 JSON 读取误停，未证明影响已完成 CM 构建；未来驱动只加四次 10 ms 有界重读，破损不当健康。完整离线控制目前 81 项通过；它们验证仪器，不等于产品质量、全仓回归或宿主验收。
