# 后续迭代方向

整理日期：2026-10-14。近期版本见[主路线图](../roadmap.md#current-iteration-plan)。
当前先改善日常读取，后续根据使用效果选择下面的工作。

## 知识质量与自然分类

**要改善：** 长会话中的重要事实遗漏、重复、过宽，以及同义分类难找。

**怎么做：** 复用现有七来源、17 判断点的测试资料，补长会话、多知识点、
纠错、临时任务与同义分类案例。分别检查提取、验证和归纳的问题，
让分类随内容自然形成。

**看什么效果：** 同样的来源和初始知识下，比较漏点、错误写入、重复和
可读性。一个点尚待确认时，其他已经确认的点照常保存，待办单独保留。
真实知识整理使用已有治理与搜索回读流程；公开测试使用虚构资料。

## 整理、纠正与恢复

**要改善：** 重复读取、重复处理、中断后找不到进度，以及保存结果说不清楚。

**怎么做：** 检查单场、多场、中断恢复、读取失败、部分保存、不写入和
歧义纠正，复用现有批次与持久化实现。

**看什么效果：** 已保存内容保留且不重复，来源变化能被发现，未完成事项
可继续处理，用户直接看到新增、替换、删除了什么。

## 安装、升级与宿主使用

每次发布检查新包的干净安装和升级、Python／平台支持、命令资源、
MCP 工具与双语说明，使用可丢弃目录进行安装测试。

当前产品范围包括全部七个已支持宿主。共用的记住、检索、纠正和恢复流程
统一改善，各宿主的原生格式、入口与 Hook 分别验证。此前 Codex 的真实运行
是一个执行样本，不是只支持 Codex 的范围决定。实际应用或自然 Hook 没有运行
证据时单独注明，不冒充通过，也不把它写成产品不支持。
Hermes 后台网关故障单独处理，Doctor 的旧 profile 问题先查现状。

2026-10-14 已保留本轮接入修复：原生事件注册、会话编号、绑定项目范围、
失败状态、配置合并安全和开发脚本路径。272 项定向测试与两组七宿主隔离
结果检查通过；具体证据见主路线图。这不关闭整个宿主使用方向，真实应用
的事件发现、授权和自然触发仍按宿主分别补证。Hermes 非标准 YAML 缩进
当前安全拒绝，尚不支持自动合并。

## 性能与检索增强

先测当前日常路径的质量、调用量、token、重试和耗时，找出真正的慢点或
检索缺口，再比较排序、索引、重排或 Rust 优化的效果。

复用 SQLite 当前知识与现有可选索引。保留能改善整项任务的方案；
效果差或关键知识退化就调整方法。需要比较 Claude-Mem 时，使用相同来源
与任务，并固定两边版本和条件。

## 共享来源容器中的单场清理

针对 Hermes／OpenCode SQLite、Antigravity 共享 JSONL 等格式，逐个实现
选定会话的删除、并发处理和失败恢复。

首先选一个格式，检查删除目标、事务提交和其他会话保持原样。
尚未支持的格式保留来源，用户需要清理时给出明确说明。

## 外部网页与 API 更新复查

**要改善：** 原先根据官网或 API 保存的知识，后来已经变化。

**怎么做：** 保存可重新定位的网页／API 和待核对说法，由 Dream／Review
重新访问对应来源，将结果送回现有验证与归纳流程。

例如“API 单次最多 100 条”后来改成 50 条，就应找到变化并更新知识。
来源失效或网络失败时，说明尚未核实，后续继续处理。

设计时明确来源定位、只读请求、认证配置、重定向、限流、冲突、复查频率
和检索提示。认证信息留在本机配置，更新后的知识通过普通搜索回读确认。

根据具体使用问题，确定改什么、怎么与当前版比较、什么结果值得保留，
再写入主路线图。优先处理数据丢失、错误写入和影响日常使用的问题。
