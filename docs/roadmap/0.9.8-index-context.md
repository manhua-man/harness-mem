# 0.9.8 - Derived-index integrity and context budgets

## Scope

1. Give every batch-derived retrieval build a generation manifest: canonical
   source generation, row count, ID hash, embedding model/dimension, build
   status, and creation time.
2. Build embedding, vec0, and trigram rebuilds in staging, then atomically
   publish the completed generation. Keep FTS and relation postings on their
   existing same-database trigger transactions, because they are incremental
   indexes rather than batch builds. On failure, retain the previous readable
   state and expose the reason through Doctor.
3. Add failure injection for interrupted build, checksum mismatch, partial
   activation, and restart recovery. Verify no newer canonical row is lost.
4. Add internal context-budget telemetry to wake/distill: raw bytes/tokens,
   summary tokens, retrieved tokens, final total, and a compaction outcome.
   Keep compact responses compact; detailed values remain drilldown data.
5. Add lifecycle behavior contracts inspired by BEAM: write/search, update
   visibility, delete invisibility, idempotent delete, reset isolation, and
   unsupported capability as a structured nonfatal result.

## Implementation slices

- `S1` manifest schema and read-only Doctor probe.
- `S2` staged generation activation with compare-before-swap and rollback.
- `S3` failure-injection and property tests over insert/update/delete/rebuild.
- `S4` context-budget snapshot contract and backend behavior contract.

## Acceptance

- Four injected index failures leave the previous active generation usable.
- Doctor distinguishes expected growth, actionable drift, and corruption and
  never presents a destructive apply command for corruption.
- Context-budget fingerprints are stable and do not change candidate quality.
- Contract tests prove deleted entries cannot reappear after rebuild or restart.

## Evidence basis

sqlite-vec provides mutation and row/blob invariants; Tantivy provides staged
commit/rollback and failpoint patterns; Letta provides tested budget-aware
compaction; BEAM provides capability and failure-artifact contracts.

## Non-goals

No replacement of SQLite, graph database, cloud index, public MCP expansion, or
required Docker/Mongo/external embedding service.

## Shipped in 0.9.9

The combined 0.9.9 release contains the complete 0.9.8 implementation scope:

- `SQLiteIndex` stores staged/active/superseded derived-index manifests with
  source-generation, row-count, membership hash, model, dimension, and build
  metadata. Doctor requires active generation proof and reports a missing
  manifest, byte-level vector drift, or posting-level trigram drift instead of
  treating matching IDs as healthy.
- Embedding, vec0, and trigram builders use generation-scoped staging names.
  Publish transactions revalidate source and staging content fingerprints, so
  concurrent rebuilds cannot publish another worker's rows or overwrite a
  newer target embedding.
- vec0 rebuilds populate a generation-scoped staging virtual table and publish
  by transactionally recreating the active virtual table, leaving the previous
  active generation in place when staging or publication fails.
- exact/trigram rebuilds snapshot the global canonical Observation membership,
  validate the staged postings, compare the source generation, and publish the
  active manifest in the same transaction. Cross-project rows are preserved,
  while compacted observations remain absent after rebuild and restart.
- FTS and relation updates remain coupled to canonical insert, update, and
  delete transactions through SQLite triggers. Contract tests verify update
  visibility, delete invisibility, idempotent delete, restart behavior, and
  project isolation instead of manufacturing a second generation store.
- wake/context plans now carry `context_budget` (`raw_tokens`,
  `summary_tokens`, `retrieved_tokens`, `total_tokens`, `budget_tokens`) and a
  `compaction_outcome`; the existing compact/full surface remains unchanged.
- Failure injection covers staging validation, source changes, activation,
  rollback, and restart. Doctor fails closed when it cannot prove active vec0
  or trigram generation integrity.

No separate 0.9.8 package or tag is published. A dedicated CI and release job
installs NumPy plus the real sqlite-vec extension and runs the vector generation
contracts; deterministic fake-vector failure injection remains network-free and
does not download an embedding model.
