# 0.9.7 - Retrieval quality and lifecycle reconciliation

## Why this version exists

The current repository already has bounded Agent-active draining, backoff,
cleanup receipts, Storage v2 recovery, compact MCP views, two-stage distill,
and 1k/10k scale fixtures. This release measures and closes the remaining
correctness gaps instead of duplicating those features.

## Scope

1. Add a deterministic local retrieval fixture pack shaped by LongMemEval,
   LoCoMo, and MemoryData: single-hop, cross-session synthesis, temporal
   reasoning, knowledge update, preference, no-evidence, and conflict cases.
2. Make temporal/current-only filtering and supersession exclusion explicit in
   the internal search plan. Record candidate channel, `as_of`, and exclusion
   reason codes before deterministic fusion; this is an internal contract, not
   a new MCP tool.
3. Record per-query gold IDs, retrieved IDs, task type, timestamp, evidence
   trace, and an explicit `skipped` or `error` reason when a case cannot be
   scored. Missing evidence is never silently converted to zero or success.
4. Report retrieval coverage (`recall_any/all@5,@10`, nDCG), task outcome, and
   abstention as separate score lines. Keep the fixture LLM-free in CI.
5. Reconcile distill jobs after restart or lease expiry: recompute state from
   chunk checkpoints, record last progress/recovery reason/count, and move jobs
   past the bounded recovery budget to a terminal failed state.

## Implementation slices

- `S1` fixture schema and deterministic runner; no runtime behavior change.
- `S2` search scorecard and structural-empty versus active-success reporting.
- `S3` job-level reconciliation and parent/child terminal-state convergence.
- `S4` crash, duplicate-agent, expired-lease, and recovery-budget tests.

## Acceptance

- At least seven task categories have independent fixtures and stable IDs.
- Two identical runs produce identical result IDs and abstention reason codes.
- A crash-mid-chunk and an expired lease cannot leave a job falsely healthy or
  permanently active; retry exhaustion is explicit and bounded.
- Full Python, Rust, lint, type, package, and Windows smoke gates pass.

## Evidence basis

Hindsight supplies lease/recovery patterns; MemoryData supplies replayable query
records; LongMemEval supplies separate retrieval/answer/abstention metrics;
LoCoMo supplies cross-session temporal fixture shapes. See the corresponding
pages in [reference-projects](../reference-projects/index.md).

## Non-goals

No new MCP tool, scheduler, store, graph database, external LLM judge, or
semantic processing without an Agent.

## Shipped in 0.9.9

The combined 0.9.9 release contains this implementation:

- `SearchPlan` records requested and actually executed candidate channels,
  temporal policy, `as_of`, exclusion reason codes, and de-duplication in the
  internal SearchBackend response. Memory, Relation, and Observation filters
  run before candidate limits; unversioned Skills are explicitly excluded from
  historical snapshots.
- Distill jobs have job-level recovery count/budget, last progress, recovery
  reasons, lease-expiry reconciliation, and terminal recovery-budget failure.
  The direct claim path uses the same accounting and backoff as reconciliation.
- The retrieval fixture has 60 stable cases across seven task categories plus
  explicit `skipped` and `error` artifacts. Reports include per-query gold and
  retrieved IDs, task outcome, recall-any/all, nDCG, and abstention precision/
  recall.

No separate 0.9.7 package or tag is published. Full Python, Rust, build, and
installed-wheel qualification are gates on the combined 0.9.9 release.
