# v0.8.20 directory-first projects

> Historical shipped plan. Statements below about the "current worktree",
> missing verification, or target status describe the pre-0.8.20 planning
> snapshot and are not current 0.9.x project status.

Mode: **SHIP THE FOUNDATION** - align with the current `claude-mem`
reference first, then land only the host support we can prove from local or
public evidence.

## Release intent

- Target version: `0.8.20`
- Release shape: one focused PR, no unrelated cleanup
- Product rule: project identity is device-first and directory-first
- Trust rule: never pretend a host is supported by silently aliasing it to
  another host

## Reference baseline (highest priority)

Sources verified on 2026-07-09:

- [`claude-mem` README](https://github.com/thedotmack/claude-mem)
- [`claude-mem` release `v13.10.2`](https://github.com/thedotmack/claude-mem/releases/tag/v13.10.2)

### Verified reference facts

1. Latest public `claude-mem` release observed for this plan: `v13.10.2`.
2. Public positioning is now multi-host, not Claude-only.
3. Public install/docs surfaces mention multiple host families, including
   Claude Code, Cursor, Codex CLI, OpenCode, Windsurf, Antigravity, and
   OpenClaw-style flows.
4. The product model is still workspace-aware: project context comes from the
   directory the user is working in, not from a global "current host".

### Design consequences we inherit

1. Host/runtime is not project identity.
2. Project identity should resolve from the current workspace directory first.
3. `active_project.txt` can stay as a fallback, but it cannot remain the
   primary read-path selector on a machine with many projects.
4. "Support" means a verified ingest/read path plus tests, not just a host
   label in a hook template.
5. Unsupported hosts must stay honestly labeled as unavailable until we verify
   their transcript/storage path.
6. Hook templates should not hardcode a machine-specific Python path; the
   invoking IDE/agent runtime should decide how to run the entrypoint.

## Scope lock for v0.8.20

### In scope (max 3)

1. Make project identity directory-first across CLI, MCP, wake, ingest, and
   hook entry.
2. Ship an honest host matrix: verified adapters where evidence exists;
   explicit unavailable status where it does not.
3. Make first-run behavior device-friendly: entering a new workspace should
   auto-create or update the project profile for that directory.

### Explicitly out of scope

- Fake adapters for Grok, Hermes, OpenCode, or any other host whose transcript
  path we have not verified.
- Full database migration from `project_name` to path-derived stable identity.
- Hook runtime self-healing beyond honest diagnostics.
- Broad release-engineering cleanup unrelated to the project/host foundation.

See [defer.md](./defer.md) for the standing defer list.
