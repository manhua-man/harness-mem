# 0.9.10 - Incremental context lineage

## Goal

Make long, growing, tool-heavy transcripts cheaper to process without weakening
the byte-exact evidence boundary. The release borrows incremental and cut-point
invariants from Pi, but keeps the existing harness-mem authority model and
public surface unchanged.

The stable loop remains:

```text
wake -> search -> distill -> review -> dream
```

## Scope

1. Reuse a prior semantic projection only when the new native transcript is a
   cryptographically verified append of the prior immutable revision. Record
   the base revision, covered boundary, prefix digest, and new projection
   digest. Any truncation, rewrite, or ambiguous lineage falls back to a full
   rebuild.
2. Prefer adapter-provided exchange/message boundaries when constructing
   derived windows. Keep an assistant tool call with its matching result;
   oversized logical units may continue across chunks, but raw reconstruction
   remains exact.
3. Add a versioned context-projection receipt that identifies the token-count
   basis, before/after totals, kept and evicted source IDs, outcome, and
   drilldown pointers. A receipt describes a read-only projection; it is not a
   Memory, Rule, Observation, or second source of truth.
4. Use observed host usage when available, otherwise the shared tokenizer,
   and only then the explicit character heuristic. Make declared character
   budgets effective and distinguish truncation/eviction from genuine summary
   compaction.
5. Add deterministic append, non-prefix fallback, tool-pair boundary,
   oversized-unit, serialization, and side-effect-free budget tests.

## Acceptance

- Appending a small tail to a large revision reuses only a hash-verified
  semantic prefix; changing any covered byte forces a full rebuild.
- Every raw revision reconstructs exactly, regardless of preferred semantic
  boundaries or oversized logical units.
- No derived cut leaves a tool result without the call/exchange that gives it
  meaning.
- A context plan reports `compacted` only when a summary was actually created;
  selection-only loss is reported as truncation or eviction.
- Receipts round-trip through the existing schema and expose content-free
  source IDs and drilldown locators without expanding compact MCP output.
- The exact 27 public MCP tools, seven Daily actions, configuration surface,
  and persistence roots remain unchanged.

## Non-goals

- No Pi SessionManager, leaf-navigation UI, JSONL truth store, or automatic
  context-overflow retry.
- No fixed cross-host `reserveTokens` or `keepRecentTokens` constants.
- No promotion of compaction or branch summaries as durable truth.
- No Pi host adapter in this release. Native branch/fork lineage remains a
  later integration task after the cross-host projection contracts are stable.

## Evidence basis

Pi `@earendil-works/pi-coding-agent` and `pi-agent-core` 0.80.2 provide the
reference invariants: append-only entries, tool-safe cut points, usage-first
accounting, compaction receipts, and branch lineage. The adoption decision is
recorded in [the Pi reference page](../reference-projects/pi.md).
