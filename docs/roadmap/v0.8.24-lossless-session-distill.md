# v0.8.24: Lossless Session Distillation

## Product contract

harness-mem must preserve every textual transcript record that an adapter can
read. Long sessions may be processed in bounded chunks, but chunking must not
drop characters, turns, tool calls, or the final response.

The runtime distinguishes three layers:

```text
host transcript -> lossless source snapshot -> ordered distill chunks -> memory candidates
```

- The source snapshot is local, immutable for one source revision, and complete.
- A logical evidence set is the ordered set of all chunks for one source revision.
- An Agent may process the evidence set over multiple calls.
- A session cannot be finalized until every expected chunk is complete and the
  source revision is still current.
- Structural completeness is checked by code. Semantic conclusions are reviewed
  by the Agent before candidate promotion.

## State model

```text
discovered -> syncing -> synced -> queued -> processing -> reviewing -> completed
                  |          |          |             |
                  v          v          v             v
                failed     changed    retryable     contradicted
```

If a host appends to a previously synced or distilled session, the source gets a
new content revision. Unchanged chunks retain stable hashes; changed evidence is
queued again and the previous result remains auditable.

`limit` bounds changed-session synchronization, not discovery to the newest N
files. Recent and backlog lanes share a persistent frontier; with `limit=1`,
the lane that consumes the changed-session slot yields the next slot to the
other lane. Failed reads enter an exponential-backoff retry lane and never pin
the normal frontier. A source absent from a complete adapter inventory is marked
`missing`; its immutable revisions remain available for reconstruction.

## Storage model

`TranscriptSource` records project identity, host, native source, content hash,
size, revision, parser version, coverage, and synchronization status.

`TranscriptChunk` records an exact character range from the normalized source
snapshot. Concatenating every chunk in index order must reproduce the snapshot
byte-for-byte after UTF-8 decoding.

The transcript ledger is separate from derived Observation search indexes. An
Observation may contain a searchable rendering, but it is not the lossless
source of truth.

## Distill protocol

1. Discover all project sessions cheaply and persist source state.
2. Snapshot every new or changed source without truncation.
3. Split the snapshot at natural line/turn boundaries. Split an oversized single
   record only when required, preserving every character across adjacent chunks.
4. Queue a distill job with the exact source revision and ordered chunk IDs.
5. Let the Agent consume and checkpoint one or more chunks per call.
6. Run a deterministic structural audit.
7. Run an Agent semantic review of final outcome, contradictions, unfinished work,
   and evidence strength.
8. Promote only warranted candidates, then run normal auto-review and Dream.

## Evidence policy

- Explicit user preferences: the transcript is primary evidence.
- Episodic session facts: the transcript is sufficient for episodic memory.
- Repository or runtime claims: verify against current code, docs, tests, or
  runtime output before promotion.
- Conflicts and incomplete outcomes: retain for review; do not auto-confirm.

## Compatibility

- Existing Observations remain readable.
- Legacy truncated Observations are rebuilt when the native transcript exists.
- If the native transcript is gone, retain the old record and mark it
  `legacy_partial`; never claim lost content was recovered.
- A locator move is merged only when raw bytes prove it is the same native
  session (exact revision or append-only continuation). Reused session IDs with
  unrelated content remain separate sources.
- Existing Agent-facing tool names may remain as compatibility aliases, but
  normal users do not run ingest or hook installation commands.

## Release gates

- Long-session reconstruction has zero character loss.
- A growing session updates instead of being skipped by session ID.
- Historical queues eventually process sessions beyond the newest window.
- Interrupted chunk processing resumes without duplicate promotion.
- All supported hosts have recorded fixtures and project-isolation tests.
- Hook failures are visible in project diagnostics rather than silently ignored.
