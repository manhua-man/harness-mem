# 0.9.9 - Seven-host replay and compatibility qualification

## Scope

1. Build a true replay harness for Codex, Claude Code, Cursor, Grok, Hermes,
   OpenCode, and Antigravity: native adapter scan/capture -> ingest -> outline
   -> candidate -> Dream admission -> wake. Existing synthetic cross-host tests
   do not cover this complete path and cannot be the release gate alone.
2. Make native-source cleanup ownership explicit in the adapter registry. An
   adapter must return deleted, partial failure, or unsupported; shared
   containers must never be guessed safe.
3. Add one operator repair/sync workflow for the installation lifecycle while
   preserving the existing seven host-native Daily actions. The workflow may
   compose existing hook and command sync operations but must not add an MCP
   tool.
4. Qualify fresh install, upgrade install, legacy reader support cutoff,
   Storage v2 restore, interrupted cleanup retry, and Windows path behavior.
5. Persist run identity, source revision, host, capability set, and failure
   artifact for every replay. Unsupported host capabilities are nonfatal and
   visible, never silently skipped.

## Implementation slices

- `S1` adapter replay fixtures and source snapshots.
- `S2` end-to-end seven-host matrix with deterministic Dream inputs.
- `S3` adapter-owned cleanup contract and repair/sync operator entry.
- `S4` Windows install/upgrade/restore matrix and release qualification report.

## Acceptance

- All seven hosts complete the replay path or emit an explicit unsupported
  capability row with no false success.
- Cleanup receipts reconcile native and harness artifacts; partial failures
  are retryable and never claim deletion.
- Fresh, upgrade, legacy-restore, and interrupted-migration tests pass on the
  supported Windows installation path.
- The release report includes run IDs, environment, capability gaps, and all
  failed cases; no failure is dropped because it is inconvenient to score.

## Evidence basis

BEAM supplies adapter contracts and failure rows; claude-mem supplies explicit
producer/consumer lifecycle boundaries; Mem0 supplies scoped/paginated delete
lessons, while Hindsight supplies recovery and bounded retry semantics.

## Non-goals

No new MCP profile, no second scheduler/store, no silent deletion of shared
native containers, and no removal of legacy readers before the documented
support cutoff.

## Shipped

Version 0.9.9 contains the complete qualification path:

- A native fixture for each of the seven supported hosts runs the real adapter
  scan and capture path, checkpoints the real distill job, submits through
  `govern_memory`, finalizes through Dream admission, and verifies wake output.
- Every run writes a content-free artifact containing run/source/revision IDs,
  capabilities, per-stage outcomes, and a failure digest. Transcript and
  candidate text are never copied into the report.
- The adapter registry declares whether capture uses a per-session file, a
  shared container, or both, and whether native cleanup is safe, unsupported,
  or source-dependent. Cleanup still delegates to the existing guarded
  implementation.
- The product and qualification matrix count exactly seven hosts.
  `codex-archive` remains a readable Codex archived-session source identifier
  for old configs and stored data, but inherits Codex capabilities and is never
  presented as an eighth host.
- `harness-mem integration hooks sync --client all` is the single operator
  repair workflow for hooks and seven Daily command entry points. One failed
  host or stage is reported without preventing the remaining hosts from being
  checked.
- Windows replay covers paths containing spaces and non-ASCII text. OpenCode
  and Hermes explicitly close read-only SQLite handles so qualification and
  cleanup do not leave locked native stores.
- Release CI runs the replay against the installed wheel on Windows, macOS,
  and Linux. Windows additionally installs the v0.9.6 release wheel, seeds
  canonical and legacy state, upgrades to the release candidate, injects a
  migration activation failure, verifies rollback and retry, and exercises a
  real processed-source cleanup retry on a Unicode path containing spaces.

The release report is content-free, and asset publication depends on both the
fresh-install matrix and the Windows upgrade lifecycle gate.
