# v0.9.5 — Evidence-Grounded Dream Admission

Status: shipped in v0.9.5 together with all work originally planned for
v0.9.4; no separate v0.9.4 package or tag is published.

> Historical contract: this file records what 0.9.5 shipped. The planned
> [0.9.13-0.9.15 four-stage convergence](0.9.13-four-stage-memory-quality.md)
> supersedes the current interpretation that authentic user-statement evidence
> plus policy confidence is sufficient durable admission. Future behavior adds
> a separate assimilation decision and stops using provisional truth as the
> default destination for ambiguous autonomous output.

## Product decision

The stable user loop remains:

```text
wake -> search -> distill -> review -> dream
```

`review` stays an optional audit, correction, reject, supersede, and undo
surface. It does not become a daily promotion gate. Version 0.9.5 changes the
automatic admission policy behind `finalize_session_distill`; it does not add a
new user command, MCP tool, config mode, storage root, or scheduler.

The internal completion path becomes:

```text
distill candidate
  -> evidence envelope validation
  -> Dream admission policy
  -> promote | reject | historical/supersede suggestion
  -> completion_disposition
  -> existing scheduled Dream maintenance
```

## Why this version exists

The current automatic review can reject obvious noise and admit candidates
using category, length, confidence, and the presence of an evidence id. That is
not enough to distinguish:

- a version or code claim verified against the current repository;
- an explicit user preference or decision;
- a statement that appears only in a transcript;
- a claim contradicted by current repository state or newer evidence.

`RelationFact` also lacks the same bounded automatic admission decision used by
MemoryEntry and RuleCandidate. Scheduled Dream is currently a metabolism,
deduplication, merge, and staleness pass; its interval/idle gate is not a
per-finalize candidate admission proof.

## Data contract

Keep evidence origin and verification result as two orthogonal fields on new
MemoryEntry, RuleCandidate, and RelationFact payloads:

```text
evidence_basis = repository | user_statement | transcript

verification_outcome =
  verified | unverified | contradicted | not_applicable
```

Add content-free audit metadata:

```text
verification_reason_codes: list[str]
verification_refs: list[EvidenceRef]
verified_at: datetime | null
```

`EvidenceRef` is a typed integrity reference, not a copy of evidence content:

- repository: project-relative locator digest, current file digest, and
  optional line/excerpt digest;
- user statement: source/revision/exchange digests plus the verified `user`
  role;
- transcript: source/revision/chunk or exchange digests.

Legacy payloads load with both fields absent. Existing truth remains readable
and is never retroactively downgraded or guessed into a new category. Every new
candidate produced by the 0.9.5 distill path must have a complete envelope
before terminal admission.

## Trust boundary

The Agent may propose an evidence basis and semantic connection, but the
runtime validates reference integrity and currentness:

- repository digests must still match the active project before finalize;
- a user-statement reference must resolve to a user-authored exchange;
- transcript references must resolve to the exact immutable source revision;
- missing, changed, cross-project, or malformed references become
  `unverified` or `contradicted`, never `verified`;
- verification metadata persisted after source cleanup contains no transcript
  text, absolute path, session id, or reversible source alias.

This validates the evidence envelope, not arbitrary natural-language truth.
Generic semantic judgment remains Agent-led and fully audited.

## Dream admission policy

| Candidate claim | Required evidence | Automatic result |
|---|---|---|
| Code, API, file, version, release, test, or repository-state fact | `repository + verified` | Eligible for normal risk/confidence promotion. |
| Explicit user preference, correction, or project decision | `user_statement + not_applicable/verified` | Eligible for promotion; rules remain subject to rule-risk policy. |
| Repository-verifiable fact backed only by transcript text | `transcript + unverified` | Reject as durable truth; keep only non-truth evidence while retained. |
| Low-risk episodic transcript note | `transcript + unverified` | Reject or retain as Observation; never masquerade as current project truth. |
| Any contradicted candidate | any basis + `contradicted` | Reject; emit audited conflict handling for matching current truth. |
| Legacy current truth with no envelope | absent legacy fields | Preserve unchanged until new evidence explicitly supersedes it. |

Contradiction handling must reuse existing supersede/stale candidate and event
ledger paths. Dream must not directly hard-delete or silently rewrite current
truth. A contradicted version/release claim should produce the same historical
outcome whether detected during finalize, later Dream maintenance, or temporal
query filtering.

## Code convergence

Create one internal evidence-admission owner, for example
`commands/evidence_admission.py`, containing:

- evidence-envelope validation;
- pure MemoryEntry, RuleCandidate, and RelationFact policy decisions;
- reason-code and audit projection;
- terminal application through existing governed store transitions.

Then converge callers:

- `finalize_session_distill` invokes the admission owner once;
- scheduled `dream_auto_tick` remains the existing maintenance pass and may
  consume admission/conflict events;
- the existing public `auto_review_candidates` tool delegates to the same
  evaluator for compatibility and preview, rather than maintaining a second
  policy implementation;
- `commands/auto_review.py` becomes a compatibility wrapper or is reduced to
  presentation helpers after all direct callers migrate.

The public MCP allowlist remains exactly 27 tools. Do not create
`verify_candidate`, `dream_admit`, a strict profile, or another review queue.

## Status and audit output

Extend existing details without bloating compact responses:

- candidate detail and Dream ledger show basis, outcome, and stable reason
  codes;
- finalize promotion summary reports counts by admission result;
- full project status reports seven-day verified, user-stated, unverified
  blocked, and contradicted counts;
- compact status only raises an action when contradictions or admission
  failures require attention;
- `completion_disposition` remains only `promoted | no_candidate`.

## Execution slices

### 1. Contract and backward compatibility

- Add shared EvidenceBasis, VerificationOutcome, and EvidenceRef schemas.
- Add optional fields and lossless `to_dict/from_dict` handling to all three
  governed candidate types.
- Extend existing `govern_memory(action="suggest")` arguments; add no tool.
- Prove old JSON/canonical rows round-trip unchanged and existing truth remains
  readable.

### 2. Evidence integrity verifier

- Verify repository, user-statement, and transcript refs project-locally.
- Recheck repository/source revision currentness immediately before admission.
- Fail closed on malformed, missing, cross-project, changed, or private refs.
- Sanitize refs through processed-source cleanup while retaining content-free
  evidence outcome and audit hashes.

### 3. Dream admission engine

- Implement the policy matrix for MemoryEntry, RuleCandidate, and RelationFact.
- Replace confidence-plus-evidence-id admission with envelope-aware decisions.
- Keep all candidates terminal after finalize; no recurring manual inbox.
- Record deterministic reason codes and existing state/retrieval signals.

### 4. Conflict and historical convergence

- Route contradicted current truth through existing stale/supersede candidates.
- Reuse temporal version conflict checks as one repository verifier, not a
  separate truth system.
- Prove old release/version truth is removed from current wake results and is
  available only through explicit history/audit paths.

### 5. Evaluation, status, and narrative

- Add a deterministic evidence-admission golden matrix covering all three
  candidate kinds, the policy combinations above, tampering, repo changes, and
  legacy payloads.
- Add transcript -> distill -> admission -> cleanup -> wake end-to-end cases for
  Codex plus at least one directory-bundle host and one unsupported shared host.
- Add compact/full response-budget tests and seven-host command convergence.
- Remove stale schema comments that describe procedural memory or wake buckets
  as future v1.x work; keep historical release records only in historical docs.

## Acceptance gates

0.9.5 is complete only when:

1. A repository-verifiable technical claim cannot reach readable truth without
   a current `repository + verified` envelope.
2. An explicit user preference or decision can promote automatically without a
   second manual confirmation.
3. A transcript-only code/version claim completes as `no_candidate` and does
   not remain pending.
4. A contradicted claim is rejected and matching current truth is handled
   through audited historical/supersede governance.
5. RelationFact follows the same evidence policy instead of being silently
   omitted from automatic admission.
6. Legacy truth with absent fields remains readable and byte/meaning compatible.
7. Processed-source cleanup leaves no raw evidence while preserving only the
   content-free admission receipt and truth metadata.
8. The MCP public surface remains 27 tools; no new config, profile, store,
   scheduler, or Daily command appears.
9. Existing 60-case retrieval golden, new evidence-admission golden, scale,
   migration, full Python, Ruff, Mypy, Rust, build, and fresh-install gates pass.

## Explicit non-goals

- Generic web or remote-service fact checking.
- Background LLM promotion without an active Agent.
- A global `strict_distill` mode.
- Manual per-candidate approval as the normal path.
- Retroactively relabeling every legacy truth.
- Shared-container transcript deletion or a second source-cleanup scheduler.
- Splitting storage modules solely to reduce line counts without a measured
  ownership or performance benefit.

## Release verification

The combined 0.9.5 implementation satisfies the gates above with:

- one shared evidence contract on MemoryEntry, RuleCandidate, and RelationFact;
- runtime project-bound path, digest, user-role, exchange, and transcript-ref
  validation before scoped automatic admission;
- terminal rejection for missing/transcript-only evidence and receipt-first
  historicalization proposals for exact matching contradicted truth;
- processed-source cleanup that removes transient locators while preserving
  only content-free digests and governed truth;
- exact 27-tool public MCP descriptors and synchronized seven-host distill
  instructions;
- 453 passing Python tests (9 environment/optional skips), the six-case
  retrieval benchmark module, six Rust tests, Ruff, Mypy, native wheel/sdist
  build, and Windows wheel-only fresh-install/MCP bootstrap smoke.
