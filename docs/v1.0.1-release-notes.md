# `harness-mem` v1.0.1 Release Notes

发布日期：2026-04-24

## 这版解决了什么

`v1.0.1` 的重点不是继续扩功能面，而是把 v1 主链路从“工程师自用”收口到“普通用户也能更顺地跑通”。

核心变化：

- 新增 `harness-mem quickstart`
  - 一步初始化、设置活动项目、自动发现最近 sessions，并尽量帮用户走到下一步
- 新增 `harness-mem doctor`
  - 展示当前项目状态、最近 sessions，并明确建议下一步是 `ingest`、`ds` 还是 `wake`
- 新增 active project 记忆
  - 用户不必在每条命令里重复输入 `--project`
- 新增短别名
  - 例如 `qs`、`ds`、`wake`、`tl`、`rules`
- 新增交互式 `correct`
  - 缺字段时会逐项提示，而不是要求一次性手打一长串参数
- 新增交互式 `handoff`
  - 任务摘要、状态、next step、blocker 可以逐项输入

## 对用户的直接影响

这一版之后，推荐起手式变成：

```bash
harness-mem quickstart
harness-mem doctor
harness-mem correct
harness-mem handoff
```

对比此前版本，`v1.0.1` 的改进重点在于：

- 更短的 happy path
- 更少的重复输入
- 更明确的下一步引导
- 更少“我现在到底该敲哪条命令”的犹豫

## 版本定位

`v1.0.1` 代表的是一次 **v1 稳定化 / 体验收口版本**，不是新阶段路线图版本。

它不改变主路线图：

- `v1` 先闭环
- `v1.x` 补体验与可解释性
- `v1.5` 扩平台
- `v2` 做高级记忆

但它把一个重要信号变得更明确：

> `harness-mem` 当前的主要矛盾，已经从“功能是否存在”转向“功能是否足够好用、稳定、按文档可复现”。
