# 网页文案草稿 · harness-mem

## 换个项目，也能问起上次为什么这么定

你记得团队改过一处界面，却想不起为什么只改了两个标签。用 harness-mem 把那次讨论整理进本机知识库。下次开新聊天，直接问当时比较过什么、最后怎么选，Agent 就有据可查。

[查看项目与接入说明](https://github.com/manhua-man/harness-mem#readme)

### 从一次讨论，到下一次决定

**说一句“整理上次的对话”。** 当前 Agent 找到已结束的讨论，分段读原文，把值得保留的决定、理由和适用条件存下来，告诉你这次记住了什么。长对话中途暂停，下次可以从已保存的进度继续。

**在新聊天里问“当时为什么这么改？”** Search 默认跨项目查已整理的知识。Agent 可以读回完整正文，用原来的条件回答，也会指出哪些细节还缺依据。

### 一个实际找回的决定

一次界面审阅只调深了两个标签的文字颜色。后来在新聊天里追问原因，Agent 找回了当时的判断：同一种文字颜色在白底上够清楚，放到这两个标签的浅灰底上却低于当时采用的对比度门槛。于是只改两处未选中的文字，保留悬停和选中时的样式。

这次验收由 Codex 整理一场 Claude Code 对话。另一场 Codex 聊天在“历史问题先查记忆”的约定下提问，首次跨项目检索的第一条就是刚保存的完整正文。

### 在自己的开发环境里使用

知识保存在当前用户的本机数据目录。接入同一知识库的 Agent 可以共享已整理的内容。要在聊天中使用，宿主需能发现两份 Skill 并调用本地 Python 包；可整理的历史取决于工具使用的会话格式。

## 制作备注（供网页制作者使用）

- 面向常切换项目和聊天、需要追溯技术决定的开发者。页面主按钮引导读者查看源码与接入条件。
- 案例是 0.0.1 候选版的隔离验收，已完成五段阅读，新增一条知识。首条命中的结论限于该问题和该次调用。只加载 Skill 的对照聊天选择了 Git，没有发起 Search。文中对比度结论转述原会话的判断。
- 案例适合用“当时改了什么 → 换一场聊天追问 → 找回原因”的文字对照呈现。引用内容已概括，排版时保留“实际案例”与示例提问的区别。
- 产品行为依据见[候选版源码](https://github.com/manhua-man/harness-mem/tree/8b1e29c4e79ec14715c689fda7200bb3fc267fd6)、[整理说明](../features/distill.md)和[检索说明](../features/search.md)。页面按钮指向公开项目和功能文档。
