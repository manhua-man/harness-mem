日期：2026-10-17，Asia/Hong_Kong。真实 Codex 主流程、原生 claude-mem 对照和六场固定短场景已执行。本轮质量不通过：固定条件29/30，另有明确未定状态未进入当前知识。模型在新建任务 home 时继承全局变化，前三场Luna、后三场Sol；逐场HM与基线一致，但不具六场同一模型验收资格。完整结果、全量已知消耗和旧未知用量见 [convergence-goal-20261017.md](convergence-goal-20261017.md)。操作员已取消旧测试停止门槛；下文数值限额保留为当时计划，不是当前门禁。本轮已结束，未自动安排下一轮。
本计划取代此前“500 万 token、540 次回答”的未批准草案；不继承其执行许可。
预算数字见 [benchmark-budget-20261017.json](benchmark-budget-20261017.json)。操作员已批准本轮时限、样本数和体验门槛；这不代表模型限额已落实，也不是实测结果或成功承诺。

## 1. 这轮只解决一条日常主线

目标是：正常聊天时按已授权设置记录有用信息；新会话能找回；用户说出纠正后使用新信息，保留仍有效的其他条件。用户不管理数据库、编号、候选、目录或内部阶段。

当前阶段是未发布工作树的收敛验证，不宣布成熟或升级版本。已有自然语言入口、后台开关、知识替换和写后检索核对；存在这些能力不等于整个日常体验通过。此前出现过归纳/替换丢限定和无依据新增；也不能把这些具体失败泛化成“没有更新机制”。

本阶段主方向：减少用户管理负担，同时保证记忆准确且有可核对的使用成本。最大差距是没有同条件的日常体验与完整成本结果，而非缺少命令或再增加功能。

| 关心的问题 | 本轮要交付的可见结果 |
| --- | --- |
| 好不好用 | 一条完整的记录、跨会话使用、纠正、再次使用流程，不只演示数据库写入 |
| 方不方便 | 日常自然语言即可；自动模式一次明确授权；不反复安装、审批或解释内部步骤 |
| 心理负担 | 不要求用户逐条质检；系统自己回读；失败/歧义给短且可行动的消息，不假报完成 |
| 消耗少不少 | 记录、整理、更新、检索、作答、重试分别计量，再给完整使用周期总账 |
| 速度快不快 | 分开量工具响应、用户前台等待、后台完成时间；不拿批量导入代替日常延迟 |

当前只选 Codex 这一条真实宿主路径完成收敛；其他六宿主仍是产品目标，不宣布已验证，也不为此删除其接入。七宿主验收、大批历史导入、公开榜单、发布和全局部署均不属于本轮。

## 2. 先复用现成工具，不再造评测体系

- [PrecisionMemBench](https://github.com/tenurehq/precisionMemBench)：接其 provider adapter，检查检索精确性、噪声、更新后旧值是否仍混入，以及延迟。保留上游评分逻辑和版本；能力不支持就如实标 unsupported，不能伪造 persona/pinned 等产品能力。
- [LongMemEval](https://github.com/xiaowu0162/LongMemEval) / [Mem0 memory-benchmarks](https://github.com/mem0ai/memory-benchmarks)：复用其数据、更新/时间/拒答分类和适用评分入口。不是跑整个榜单；默认模型裁判和生成不能自动开启。
- 现有 code/scripts/run_matched_memory_comparison.py 只作为已有配对执行、输入封存和采集代码的复用候选；它不是上游正式套件，也不是已实现的预算闸门。不原样启动其中的旧样本。
- 现有隔离探针和定向测试用于适配器、事务和读回归；不得把通过这些检查写成自然 Hook、模型归纳或日常体验通过。

仅增加必要的薄适配，不复制其他项目的运行时、云服务、队列或数据库。直接预置当前知识只能测底层检索/更新，不能算自动抽取成功。原生语义写入必须走各产品自己的流程，适配器不得代替模型挑事实或补答案。

## 3. 一个有限周期，四步结束

本轮工程工作最多 6 小时，真实模型执行累计最多 1 小时；等待用户不计入。超时不自动延长，未完成就是未完成。

### 第一步：无模型资格检查与基线（最多 2 小时）

复用现有代码和上游接口，确认隔离数据、adapter、可用宿主、计量和限额能力。
固定以下资料后才允许下一步：
- 当前版、上游版本与适配器字节；模型/推理/服务配置与实际调用路径。
- 仅属于本任务的临时存储与测试服务；上游 reset 绝不连接真实记忆库。
- 题目、来源、判断规则、支持/不支持的能力，以及用户操作步骤。
- 所有生成、裁判、原生重试和辅助模型的调用是否都可观察、受控；无法控制就不开跑。
- 固定一组知识做 30 次无模型只读请求，报告测得的热态工具延迟；冷启动另列，不能冒充最终回答延迟。

这里允许预置知识的隔离检查，不把其 0 模型 token 推广到整条记忆流程。调用模型的上游 seed、embedding 或 judge 阶段保持关闭，直到单独纳入获批预算。

不编译私有 CLI，不改代理、沙箱、账号、个人技能或共享 MCP。现有宿主走不通时，只定位我们接入层的明确问题；需要修宿主本体则停止报告阻塞，不扩成环境工程。

### 第二步：一条日常流程的小样本止损检查（最多 100,000 测试 token）

在同一个短场景中完成：增量自动记录 -> 新会话自然提问 -> 新事件纠正 -> 新会话使用最新信息，同时检查其他有效条件未被丢弃。
比较 harness-mem、claude-mem 和不使用记忆工具的工作方式：
- 同一原始信息、模型、机器与任务；基线仍能读取同一批历史文件，不能故意让基线没有信息。
- 分开记录自动处理完成时间和前台等待；不能先后台跑完再把后台成本隐藏。
- HM 和 CM 保持各自原生表示与算法，不用 HM 的行数或 schema 判 CM 错。
- 全部失败和重试计费；按请求 ID 排重，未知用量不是 0；不能继续跑另一边凑胜利。
- 这一阶段发现不能记录、不能更新、不能回读、无依据写入或不可接受的成本时，先停，不扩大样本。

这只用于判断值得修什么，不是统计排名或公开分数。若 100,000 不够完成，记录实际覆盖和消耗后停止，不能换更简单的样本宣称过关。

### 第三步：最多一轮有边界的修复（最多 4 小时）

只修第一步和第二步直接定位到的根因，优先影响日常主线的 1—2 项；不是每项分别再开多轮。
- 操作负担：沿唯一 hm 入口简化说明和结果展示，不添加新命令或强制问卷。
- 更新正确性：沿当前验证、吸收、事务和普通检索 owner 修复，保留主体、范围、未知状态及有效限定。
- 消耗/速度：先定位重复调用、无效重试和启动等待，只重用确实完整且未变化的输入/结果；不靠删来源、放松验证或缩减用户技能降成本。
- 后台生命周期：增量推进已有 job，不把已经处理的全部历史反复重做；不在日常查询中启动全量导入。

不允许“再加提示 -> 再跑一轮 -> 再加提示”的无上限循环。修复后只做受影响的离线检查，然后进入一次独立复验。

### 第四步：一次独立复验和实际体验

使用 6 个未参加上述修补的短完整场景：普通记忆、跨会话使用、信息纠正、有效条件保留、主体/范围区分、未知/无依据拒答。
场景在执行前固定，不使用原 180 场/13 场及换名变体，不按输出换题。公开样本只能称未用于本项目调参，不声称底座模型从未见过。超出预算的完整来源不能截断成好答版本。

需要作答质量的场景走真实 Agent、MCP 和各自原生写入链路；不直接塞金标准。源信息没进入记忆、检索没找回、模型答错分别报告。自动模式须有自然触发后新产生的完成结果，而不是手动调用 worker 冒充 Hook 成功。

然后由用户只做普通使用：说一次记录、问一次、纠正一次并再次问。不要求用户阅读测试文档、管理编号或替开发逐条判卷。用户仍觉得麻烦，就不宣称“方便、低心理负担”。

## 4. 事先定好什么叫值得继续

以下是本轮已批准的验收门槛，不得为了通过降低：
- 6 个场景的关键当前事实和必要限定全部正确；没有旧值冒充当前、跨主体挪用、无依据新增或错误批准。小样本通过不代表全库无损。
- 日常流程不要求目录、编号、候选管理或重复审批；自动记录只在一次明确授权后发生。关键歧义允许一次必要澄清，不伪装成确定事实。
- 本机热态纯检索工具响应的观察 P95 目标不超过 1 秒；不调用额外语义生成。最终回答与后台整理另量，同条件对照 CM，不将该 P95 说成 SLA。
- 相同正确完成范围内，完整周期的 input + output、缓存、重试、工具/用户等待都可核对；模型缺 usage、条件失配或未完成不能宣布更省。
- 继续自研至少需要一项有实用意义的优势。建议价值门槛：相对同质量 CM，总 token 或用户等待少 20%，另一项不恶化超过 10%；或者存在本轮确实验证、且用户明确需要的 CM 缺失能力，并由用户接受其代价。百分比是决策目标，不是已测收益或统计保证。
- 若质量不合格，或成本/速度都不占优且没有用户需要的独特价值，默认不再增加自研投入。不能临时编一个差异点挽留项目。

结果只有三种建议：继续有限日常试用；保留必要入口/适配而复用上游；停止项目并保留源码和数据。采用上游、迁移真实记忆、修改全局安装或发布，均须另获授权，不自动执行。

## 5. 消耗控制：先把能保证和不能保证的说清

受控测试模型调用整轮最多 500,000 input + output token（含缓存输入），首批最多 100,000；前后阶段不重新起算。失败、裁判、修 JSON、探针及隐藏重试均包含，最多 80 个真实请求、累计 1 小时。不是目标花费，更不保证这些额度能完成全部计划。不开额外工程/审查子模型。

操作员随后明确接受按每次实际 usage 累计停止，取消单请求输出上限和绝不在最后一笔越过 token 阈值的前置要求。这是累计停止阈值，不能再宣称是请求执行中的绝对 token 硬限。保留完整输入、所有失败/缓存/重试用量及未结算部分；缺 usage 必须停止，不能估成零继续。本次真实调用已按该修订执行，并因未结算用量和产物越界而停止。

不为它另造复杂计费系统或重编译 CLI：复用现有宿主生命周期和采集能力；原生请求/流重试在本次任务配置中验证为0。隔离、用量观察或停止条件失效时，后续真实模型执行额度为0；单请求输出上限不再作为阻塞理由。

必须交两张账：产品完整使用成本；本次工程、聊天、准备、测试、失败和交付的任务成本。当前这条聊天/平台开销不能由测试 runner 强制限额。已知就列实测，取不到就列未知，绝不当免费，也不把 500,000 说成整个任务总耗费上限。
若操作员要求包含聊天和工程的绝对总硬限，必须先确认宿主能落实；做不到就停止，不擅自缩小计费口径后开工。

## 6. 防止项目再次膨胀

- 当前有限周期允许薄适配、无模型资格检查和有界修复；模型生成仍须独立通过预算闸门。不开额外子智能体或新聊天。
- 执行时最多两个工程工作包：适配/定位、一次修复；不在这条长聊天里反复轮询和重读原始大报告。
- 测试产物放仓库外的单个任务目录，新产物与新增依赖/缓存合计最多 200 MB；已存在的参考镜像及正式运行环境不算新增。到线停止，不先创建 GB 级目录再解释。
- 使用临时虚构数据；真实 575 条知识、原始会话、全局配置、个人技能、当前共享服务不动。
- 复用既有清理入口与严格路径/进程检查。日常回复只给结论；保留小结、用量和必要失败证据，不堆成新的报告工程。
- 最终一页交付：五项体验结论、同条件对照、总消耗及未知、是否值得继续、剩余缺口；失败就建议停或复用上游，不自动追加一轮。
