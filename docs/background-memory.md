`semantic.execution.profile` 与 `[semantic.providers.*]` 为**已删除路径**；配置加载时会剥离，不参与后台授权或执行。

## 后台会做什么

```text
任务开始 → 宿主支持时原生注入相关记忆；其他情况由 Agent 经 MCP 检索
每次回复/任务结束 → 完整来源准备 → Dream/worker → 所选 CLI → 验证 → 新增 / 更新 / 不写
```

- **Hook 蒸馏**：每次完成回复或任务后尝试处理新来源；保留来源和可恢复队列
- **Dream 复核**：对照已有知识和来源（同一个所选 CLI）
- **人工审查**：通过 `hm` 检查、审阅、纠正或删除已有记忆；不承担日常记忆启动

任务相关注入有宿主边界：Codex、Claude Code 使用 UserPromptSubmit 动态查询，Hermes 使用调用前事件。Antigravity PreInvocation 本身没有提示文本，Hook 从该事件指向的、与 conversationId 精确匹配的原生 transcript 尾部读取最新 USER_INPUT，交给同一 `build_wake_injection` 检索；只接受本机原生 brain 会话目录，忽略助手、工具和注入消息。同一用户步骤不在连续工具调用间重复注入；新的用户步骤再次召回。无法读到当前问题时保留可用提示和 MCP 路径。Grok 的 UserPromptSubmit 输出被宿主丢弃，故保留 SessionStart/Stop，任务查询走 Agent MCP；OpenCode system.transform 注入会话可用提示，任务查询仍走 Agent MCP。七宿主的原生任务相关注入并未全部实现。

2026-10-19 本机配置纠正：用户级与本项目的 `distill.autonomous.cli` 均恢复为 `current`，按触发 Hook 的宿主使用其自身 CLI。上一安装记录中的全局 `antigravity` 选择已撤销；本次重点是回答前的 Hook 召回，未运行模型测试，也未把静态检查记为自然触发验收。

### Codex / Antigravity 的空闲处理与简短提示（2026-10-19，未发布）

- 召回仍在新问题回答前进行，使用当前问题查询当前知识。反重力同时覆盖 App、CLI 和 IDE 的原生 brain 目录，来源发现与完整读取沿用同一 adapter。
- 只有可用提示、没有当前问题时不伪称已召回。Codex 的 `systemMessage` 提示实际召回数量、仅找到可展开内容或暂无匹配；记忆正文放在原生 `additionalContext`。反重力没有独立通知字段，通过 `ephemeralMessage` 要求当前 Agent 在首条用户可见回复中简短提示；这是指令遵循，不是确定展示的原生通知，也不额外发起模型调用。
- 完成回复后的 Stop 仍进入同一后台队列。Codex、反重力的 detached worker 等待约 30 秒；同会话的新 Stop 重置窗口，新输入取消此前等待。取消不写知识，下一次 Stop 继续准备完整来源。已经开始处理的一轮可以完成，不承诺撤回已发送调用。
- 不同会话保留各自请求；只从本进程已观察到的同会话闭合快照退休请求。就绪会话不会被另一会话不断重置的等待阻塞。
- 用户级 Hook 是完整接入，不再要求项目级副本同时存在。当前项目的等价 Codex 项目 Hook 被清理；后续安装沿用用户级注册，保留所有非 HM 条目和已有原生信任配置。反重力召回收据按会话保存当前步骤，避免同项目多会话覆盖去重状态。
- 安装备份和静态核对记录：`.tmp/hook-idle-notice-20261019/installation-receipt.json`。没有运行模型或 UI 测试；不能据这些文件声称真实空闲学习、召回质量或通知显示已经验收。

Antigravity 后台执行使用原生 `agy`、完整 stdin 输入和 JSON Schema。每次调用在临时工作目录选择专用 worker，配置空工具、MCP、技能和插件列表，并关闭命令执行；不续接用户对话。只接收单轮成功的结构化结果，工具活动或非空工具清单会使结果失败；用量取最终结果，避免重复累计步骤用量。提取、验证、整理继续由同一 HM 流程接管。原生 Hook 和认证仍由宿主管理；配置安装和静态检查不能证明自然触发后的学习成功。协议依据：[headless](https://antigravity.google/docs/cli/headless/) 与 [custom agents](https://antigravity.google/docs/subagents/)。

## 回执（receipt）看什么

成功的一次后台运行：

```json
"provider": { "name": "hermes_cli", "host_client": "hermes" }
```

| 字段 | 成功时 |
|------|--------|
| `provider.name` | `{host}_cli`（如 `codex_cli`、`hermes_cli`、`claude-code_cli`、`opencode_cli`、`antigravity_cli`） |
| `hook_guard_check.all_blocked` | `true` |
| `hook_guard_check.downstream_jobs_created` | `0` |

后台调用的是所选 CLI Agent；harness-mem 不改写该 CLI 的模型、服务地址、账号、
密钥或全局配置。任务所需来源已经完整放进输入，所以调用不加载无关工具；它还会阻止
后台 Agent 重新进入 harness-mem Hook，并在本机校验返回 JSON。

未发布工作树的 Codex JSON 调用通过进程与线程参数关闭配置中的 MCP、项目文档、
插件技能目录、Hook 与交互工具，使用临时的窄任务指令和只读权限；不删除技能，
不修改用户配置或日常 Agent 的上下文。检测到命令执行、MCP、文件变更、浏览器或协作工具活动时，
返回结果会被拒收；CLI 仍可能携带原生控制工具定义，不能据此宣称严格零工具能力。

Codex 执行器在一次 worker 批次中复用原生 `app-server` 进程，每次语义调用仍建立
全新、无历史的 ephemeral thread，完整传入原提示和 JSON schema；不续接旧对话，
不合并提取、验证、吸收。原有 CLI 首页指令保留并校验来源与正文哈希，不注入额外
项目指令。配置、模型、推理强度、请求 tier、MCP 隔离、终态及线程关闭均核验。
批次只关闭自己创建的执行器；外部传入者负责关闭。进程、租约、临时目录与子进程
沿既有清理 owner 释放，失败不会偷偷回退到 `exec` 或重发不确定的请求。
回执的逐响应用量不重复叠加累计计数，已知小计与未知尾部并列保留；它不单独证明
所有底层 HTTP 尝试或账单。当前13源回归已关闭并逐响应核对实际HTTP用量，
仍不代表完整180源性能或语义质量通过。
提取先读取选定来源的全部用户及助手正文；逐点验证同时提供完整会话上下文，
保留引用窗口内的中间助手回复。同一证据正文只传一份，各引用仍保留角色、位置与 hash；
不以摘要代替原文。归纳按最多八个独立点的有界批次处理，批次经原有纠正仍失败时
退回单点，全部候选仍须独立验证和处置；失败、回退及未知用量不能被后续成功覆盖。
归纳仍通过同一证据门、SQLite 写入和普通检索回读。项目内决定必须在知识正文里保留
其主体和适用范围，不能被改写成全局偏好。人工审查和纠正仍在当前 Agent 中执行。
替换既有知识时，原子候选的措辞不能丢弃仍有用且有来源支持的既有限定；必要的旧值/新值
或阶段关系应留在同一条后继知识正文中，而不只写在内部理由里。不能把旧当前行复活、
建立知识历史，或把已证伪旧说法当成真实前态；来源不足以证明停用关系时，只保留有依据的
阶段事实，不补造精确日期、排他性、批准或部署。
条目间的主体、限定语或标点相似，不足以证明语义总括或重复；本地规范化只折叠完整载荷
完全相同的条目，不因逗号数量、共享词或缺少特定短语删除其他独立知识。原子候选的纯正文
回退只适用于无目标新增，不能用于 refine/replace 删除现存知识；无效替换继续明确的模型
纠正或 defer，不把候选子句当作既有事实的完整后继。缺少批准证据也不等于已经证实未批准。
有未来用途的提案身份和证据解释边界应进入候选，而不只藏在审阅记录里；保留提出者与
来源、材料或时期范围，不把它们当成已采用规则或无范围的长期当前事实。
带有持续用途的事件/审批/未变更边界，不只是临时状态报告；提取须保留其事件身份
和限制，不能只写入待办或因另一项目的决策更显眼而遗漏。验证按实际有时间限定的
说法判断，不因它不能证明当前合同/实现就自动降成仅本次有用；这不把历史观察升级
为现行政策。吸收还须保留新验证点自身的有用限定，不能只放在理由里；其他当前行
仍然正确，也不能替代本次变更明确未影响哪些规则的关系。
与禁止性约束相邻的描述性事实不能被改写成额外的肯定义务，例如要求披露该事实或执行它；
已核实备选方案的明确动机也须保留，不自行补造原因。含替代/历史措辞的候选仍进入
原有证据、长期价值和吸收判断，运行时不按关键词把整条候选提前丢弃。
当前 transcript-only 观察即使有说话人、时期和讨论范围且语义核验通过，也不能
通过原有长期真值准入。操作员随后明确允许保留带说话人、时期和来源范围的转述，
但不能视作外部现行事实或用户批准。独立的 typed source_report 准入与跨权威写入
保护已通过818项定向测试（一个真实POSIX跳过）、静态检查、两个隔离结果和独立复验。
另一次实际模型控制拒绝逆角色批准归属，支持合法改写与助手报告身份；一个请求
为4,876个已报告token、未知用量为零。它不代表能机械识破manual语义verifier故意谎报，
不放开 transcript-to-fact 门禁，不另建知识库。相同13场来源的新空库回归正在运行，
完整源质量和全流程性能仍未通过。
同一主体、同一字段和适用时期内，用户已定选择及助手明确提出的备选可合成带归属
限定的一点；只有实际用户选择可用 user_statement 锚定，不能借同一引用窗口把
assistant-only 提议改成用户决定。许可或否定覆盖来源中的并列项，除非来源明确换
scope；省略重复的“可”不等于实际发生。合法 exchange 引用仍核完整来源、位置和
digest，transcript-only 正向真值门禁不因此放开。
Windows 上先暂停启动 CLI，加入仅限本次调用的进程范围，再恢复执行；调用收尾或
执行者退出时终止范围内进程，以释放输出句柄和临时工作目录，不按进程名关闭其他
Codex 会话。短命 CLI 仍须零退出码与 JSON 校验；Codex 持久进程的单次调用须原生
turn 终态、线程关闭与 JSON 校验，提前出现正文或输出文件不算成功。
Windows 的退出清理保证自成功关联进程范围起成立；创建与关联之间尚无原子绑定
证明。异常退出后的磁盘临时物恢复也不在本轮验收内。

## `hm` 与 Doctor

首次通过 Quickstart 安装宿主生命周期 Hook 并授权，之后随正常任务持续学习；
`hm` 不是每次记忆的启动开关。`get_project_status(project_root, host_client)`
保留当前工作区检查与项目 Hook 兼容准备。普通检索与审查不以项目或 Hook
准备为前提；简短的可用消息也不证明自然 Hook 已运行。
检索统计、处理进度、费用、版本、队列、后台 CLI 状态和修复证据不进入日常回复。

需要查看这些详情或排查问题时，在项目根目录运行 `harness-mem doctor`。
后台是否开启、所选 CLI 是否可用以及失败原因都属于这个完整检查，
不再由日常回复展开。
