# hm

这是 harness-mem 唯一的日常入口。用户只需用普通话说明要做什么；不要让用户选择内部动作，也不要默认展示内部任务、临时草稿、运行回执、服务名称、编号或处理阶段。

用户常用的说法只有三种：

- “记住这次”：整理当前项目会话，只保存以后还能复用的内容。
- “找一下以前怎么做的”：查当前项目已有的有效记忆；只有用户明确说跨项目时才查其他项目。
- “这条记忆不对”：先找出用户指的记忆；用户要删除就删除，用户给出新说法就替换旧说法。

执行时遵守这些规则：

1. 先调用 `get_project_status(project_root=<当前工作区的绝对路径>, host_client=<当前 Agent 宿主>)` 做一次当前项目的可用性检查。项目任务开始、准备改代码或需要作出项目决定时，按需实时查相关当前记忆；工具报错、出现冲突或准备写入时再查。普通聊天不查。这个检查和检索都不向用户展开内部细节。
   任务进行中也要按需要实时查当前记忆，但不重复无关搜索。
   需要自动判断是否该查记忆时，调用 `autopilot_search_tick`；它只返回相关当前记忆或“不需要查”，不要把它的过程告诉用户。
2. “记住这次”必须完整读取会话。一场会话可以产生多条独立记忆；逐条核对来源和当前项目，再分别决定保存、替换、删除或不保存。没有可靠证据就不写。使用现有的 `prepare_session_distill`、`govern_memory` 和 `finalize_session_distill` 完成处理，不自行增加批次、每日数量或单条长度限制。
3. 每次新增、替换或删除后，立即用普通 `search_memory` 检查结果。只有新说法能搜到、旧说法不再出现时，才告诉用户已经记住或改好。
4. 用户主动整理的会话在成功完成后清理该会话的原文、宿主历史和生成的摘要；不制作会话备份，也不清空宿主全部历史。Dream 自动整理只保留归档；失败、未完成或无法确认的会话保留原文。
5. MCP 不可用时，只说明当前入口无法使用，并提示“请在当前 Agent 或 Router 中连接 harness-mem，再重试”；不要改走另一套记忆流程。

默认回复只说实际结果：

```text
记住了：<新增、替换或删除的具体内容；没有则写“没有需要长期记住的内容”>
没记：<被跳过的内容和普通原因；没有则省略>
还没完成：<未完成事项；没有则省略>
```

处理多场会话时，不默认报会话总数、任务状态、进度、费用或对应表。只有用户明确要求完整审查时，才展开“会话 → 结论 → 证据”的对应关系。用户要详情时，直接给整理后的可读知识，不把候选草稿、原始字段或内部状态当作记忆。

始终使用用户当前的语言回复；用户切换语言时跟随最新一句。回复中不要另造产品术语，不补一套产品术语。
