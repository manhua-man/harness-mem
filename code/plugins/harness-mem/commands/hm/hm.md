这是 harness-mem 唯一的日常入口。用户只需用普通话说明要做什么；不要让用户选择内部动作，也不要默认展示内部任务、临时草稿、运行回执、服务名称、编号或处理阶段。

用户常用的说法只有三种：

- “记住这次”：整理当前项目会话，只保存以后还能复用的内容。
- “找一下以前怎么做的”：查当前项目已有的有效记忆；只有用户明确说跨项目时才查其他项目。
- “这条记忆不对”：先找出用户指的记忆；用户要删除就删除，用户给出新说法就替换旧说法。

用户用标题或内容描述纠正、替换或删除目标，不需要填写、复制或管理记忆编号。Agent 在当前项目中普通搜索并核对目标，将结果的旧标题、正文和分类作为 `arguments.target_knowledge=[{title, statement, module}]` 传给 `govern_memory`；不寻找隐藏编号、不猜测或拼造编号。自然文字无法唯一确定目标时，保留旧内容，用可读标题或内容说明无法确定哪条记忆，将该点列为还没完成。

用户说“看看现在记住了什么”时，用 `search_memory(project_name=<当前项目>, query="", scope="project")`
查看全部当前知识，按返回的自然模块展示标题和正文。无需先读取原始会话，也不要把任务材料当作知识。

执行时遵守这些规则：

1. 先调用 `get_project_status(project_root=<当前工作区的绝对路径>, host_client=<当前 Agent 宿主>)` 做一次当前项目的可用性检查。项目任务开始、准备改代码或需要作出项目决定时，按需实时查相关当前记忆；工具报错、出现冲突或准备写入时再查。普通聊天不查。这个检查和检索都不向用户展开内部细节。
   任务进行中也要按需要实时查当前记忆，但不重复无关搜索。
   检索先提取主题词，不直接把整段聊天当查询。空结果时换一种说法或拆成明确关键词再核对，不能一次没搜到就说没有记忆；仍无结果时如实说明。检索不保证理解所有同义说法。
   需要自动判断是否该查记忆时，调用 `autopilot_search_tick`；它只返回相关当前记忆或“不需要查”，不要把它的过程告诉用户。
2. “记住这次”必须完整读取会话。一场会话可以产生多条独立记忆；逐条核对来源和当前项目，再分别决定保存、替换、删除或不保存。没有可靠证据就不写。使用现有的 `prepare_session_distill`、`govern_memory` 和 `finalize_session_distill` 完成处理，不自行增加批次、每日数量或单条长度限制。
   单个点失败、证据不足或目标不明确时，保留该点相关旧内容与来源；继续让其他独立、已核实且有长期价值的点走既有提交和回读检查。共同安全问题仍按整批停止规则处理。
3. 每次新增、替换或删除后，立即用普通 `search_memory` 检查结果。只有新说法能搜到、旧说法不再出现时，才告诉用户已经记住或改好。
4. 多场或继续整理时，先用 `inspect_sessions` 只读盘点当前项目，区分已完成、待整理、空草稿、无法读取和归属不明。按用户已给范围选择返回的会话引用，用 `prepare_session_distill(batch_sessions=...)` 固定范围；后续只带 `batch_id` 继续，不重复询问已明确的范围、不自动纳入新会话。逐场沿原有完整读取、验证、收尾与搜索链路处理。批次保留原文与摘要，不附带清理；清理需用户另行明确要求。单场原有主动整理仍按成功结果和安全边界清理，不制作备份或清空宿主全部历史。Dream 自动整理只保留归档。
5. MCP 不可用时，只说明当前入口无法使用，并提示“请在当前 Agent 或 Router 中连接 harness-mem，再重试”；不要改走另一套记忆流程。

默认回复只说实际结果：

```text
记住了：<实际新增或替换的具体内容；没有则省略>
已删除：<实际删除的具体内容；没有则省略>
没记：<被跳过的内容和普通原因；没有则省略>
还没完成：<未完成事项；没有则省略>
```

包括部分保存时，优先读 `knowledge_changes` 中本次实际保存的标题与正文，结合 `not_written`
和 `unfinished_work` 直接展示成果；数量、测试通过或报告链接不能替代具体知识。
多个模块时按自然模块分组，使用用户当前语言忠实表达，不改变事实含义。原会话是否完成任务
与这次是否保存记忆分开说明。用户不需要再次追问才看到成果。
已保存与还没完成必须分别报告，不把部分保存说成全部完成；默认回复用普通话说明失败，不出现 worker 等内部名称或要求用户提供编号。没有变化时可说“本次没有记忆变化”；只有完整核对后确实没有长期价值内容，才说“没有需要长期记住的内容”，不能用它代替失败或未完成。

如果还没开始整理就无法读取必需的处理说明，立即停止，不改记忆、不自动重试，也不改走另一套流程。只说明本次尚未开始、记忆没有改动、什么暂时无法使用，以及恢复后可继续；不展开报错原文、文件路径、工具名称、编号或内部步骤，也不把尚未执行的整理步骤冒充会话中的未完成事项。部分保存后失败则保留并如实展示已经核实的成果，不能说记忆没有改动。

多场处理中可简短说明已完成和剩余数量；最终默认只报实际知识变化与未写入原因，不展开内部状态、费用或对应表。单个来源失败时保留并继续其他已选来源；重试须显式使用 `retry_failures=true`。版本漂移、跨项目绑定或写后检索失败立即停止整批，不能新建批次绕过。只有用户明确要求完整审查时，才展开“会话 → 结论 → 证据”。用户要主题概览时，以 `inspect_sessions(action="source")` 完整分页读取，再提交覆盖范围和主题证据到 `action="overview"`；允许一场多主题，未读完或依据不足留作未分类，不靠标题关键词推断。用户要详情时直接给可读知识，不把候选草稿或内部状态当作记忆。

始终使用用户当前的语言回复；用户切换语言时跟随最新一句。回复中不要另造产品术语，不补一套产品术语。
